# dsh-custom-system-prompt

按会话自定义系统提示的 DSH Web 插件。设置 → 插件 分区中的卡片：选择会话、写入提示词、保存；该会话的下一轮模型调用即带上这段系统提示。配置经 `settings` 服务持久化，重启进程后保留。

## 安装

在 `$DSH_HOME/profiles/web/package.json` 中加入依赖并列入 bundles，然后 `pnpm install` 并重启 web 进程：

```json
{
  "dependencies": {
    "dsh-custom-system-prompt": "file:path/to/dsh-custom-system-prompt.tgz"
  },
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-custom-system-prompt"]
    }
  }
}
```

## 行为

- 每个会话可配置一段独立系统提示；留空保存 = 清除注入。
- 注入段名为 `custom-user-prompt`，order 50，位于 persona 之后、工具说明之前。
- 配置存于 settings 命名空间 `dsh-custom-system-prompt`（JSON storage，重启保留）。

## 常见问题：为什么长对话里注入的角色效果变弱？

注入机制对所有会话一视同仁，没有"新会话强、旧会话弱"的区别：

- 插件加载时会对**所有已存在的 agent** 注册提示段，`agent/created` 事件兜住之后新建的会话；
- 段文本是 `text: () => sessionsOf()[sessionId] ?? ''`，**每次请求组装系统提示时实时求值**——旧会话和新会话每一轮都拿到同样的段、同样的位置（order 50，persona 之后、工具之前）。

所以"感觉角色没压住"不是插件少注入了什么，而是上下文动力学：

1. **历史惯性（主因）**：模型会强烈模仿自己最近的输出风格。长对话里几十轮"助手口吻"的历史在跟角色设定对抗；新对话没有这些历史，系统提示占绝对主导。
2. **上下文占比**：长上下文里注入段只是很小一部分 token，而且模型对**靠近末尾的指令**权重更高——段在中间，最新消息和最近回复的风格反而主导。
3. **压缩（compaction）**：长对话触发上下文压缩后，旧对话的逐字历史（尤其是反复出现的"助手口吻"）被浓缩成摘要，风格惯性随之打破；注入段本身属于系统提示组装，不会随压缩消失，每轮都在。副作用是历史里承载的角色细节也可能被摘要丢掉——所以角色约束应写在注入段里，别埋在对话历史中。

### 建议

- **已有会话角色效果变弱**：直接执行 `/compact` 压缩上下文即可。压缩后旧对话的说话风格不再逐字对抗角色设定，注入段重新占主导，角色效果随之恢复。
- **角色扮演想要最强效果**：新建会话，先配好提示词再开始聊，没有历史包袱。
- 插件本身不区分会话新旧，效果强弱 = 提示词写法 + 上下文状态（历史越长越弱，压缩后恢复）。
